# Seed token playground

A client-only Vite + React token workbench. No router, SSR, daemon, account or persistence service.

## Run and build

From the repository root, with direnv loaded:

- pnpm --filter @shm/design-playground dev — http://localhost:6007.
- pnpm --filter @shm/ui storybook — http://localhost:6006.
- pnpm --filter @shm/design-playground build — standalone static app.
- pnpm --filter @shm/design-playground build:site — app at dist/, Storybook at dist/storybook/.
- pnpm --filter @shm/design-playground test — parser, grouping, generated variables, sharing, contrast math and
  inline-policy tests.
- Root typecheck, test and formatting commands include this package.

VITE_STORYBOOK_URL defaults to http://localhost:6006. Storybook's STORYBOOK_PLAYGROUND_URL defaults to
http://localhost:6007. The combined build supplies relative ./storybook/ and ../ links; serve dist/ with any static
server. No deployment workflow is added.

## Cloudflare Pages

Production: https://seed-design-playground.pages.dev (Storybook at `/storybook/`). The combined build isolates its Vite
environment from local desktop/service settings and supplies relative cross-links.

To redeploy from the repository root, set `CLOUDFLARE_API_TOKEN` in your shell without committing it, then run:

```sh
export CLOUDFLARE_ACCOUNT_ID=3982e727ae1980b6e00d14f3011cb0a5
direnv exec . pnpm --filter @shm/design-playground build:site
direnv exec . npx --yes wrangler@4.154.0 pages deploy frontend/apps/design-playground/dist --project-name seed-design-playground --branch main
```

The Pages project uses production branch `main`; `--branch main` publishes production even when the checkout is the
Storybook feature branch. Review the checkout before deploying. No deployment workflow or credentials are stored here.

## Token controls

The fixed dark panel edits tokens, not its own chrome. On mobile, open it using the menu button. Colors are discovered
from both modes of the real @shm/ui/theme.css?raw and grouped into Brand, Surface, Text, Semantic, Chart, Sidebar and
Code. Search also filters typography, spacing, shape, elevation and motion controls. Color edits affect the selected
mode; hue/neutral shortcuts affect both. Direct color edits win over generators. Invalid color drafts are marked and
never injected.

A dot marks changes. Each edited control has a reset; a color reset restores that token even if a generator remains
active. The count is the number of distinct changed custom-property names across both modes, including variables
generated by shortcuts. Reset all retains the selected mode.

Hold **Hold to compare** with a pointer, Space or Enter to temporarily empty the single override stylesheet. Releasing,
cancelling, losing focus or pressing Escape restores edits. **Share** copies a self-contained URL hash, with a plain
address-bar fallback if clipboard access is unavailable. Section anchors do not discard the in-memory edits. There is
intentionally no Copy CSS or Shuffle workflow.

Extensions are applied only when changed, preserving the exact original defaults:

- Sans/serif/mono use the existing --font-\* variables.
- Base size and scale ratio generate Tailwind v4 --text-xs through --text-9xl.
- Line height sets `--text-*--line-height` and `--leading-*`.
- Spacing changes Tailwind's --spacing, scaling real p/m/gap/size utilities.
- Radius uses existing --radius; shadow strength scales existing shadow alphas.
- Motion uses existing --duration-normal, also wired to Tailwind's default transition duration. No speculative, unused
  extended tokens are exposed.

## One scrolling canvas

Foundations shows every discovered color, type, spacing, shape and elevation. Components and Page modules eagerly
discover every `**/*.stories.tsx` module and use Storybook's portable composition API. Module/story decorators and the
real preview annotations are retained; the preview theme decorator receives the canvas's selected mode. A sticky index
links the four sections. Story groups mount when within 600px of the viewport and retain local state thereafter; tall
stories have bounded local overflow. The index shows the complete story count and static policy-classified
Storybook-only count, independent of which tiles have mounted. Unexpected inline rendering errors still show a fallback
without changing these catalogue totals.

Stories with hardcoded open overlays, page permission/parameter modals without closed-state inputs and non-null image
crop inputs remain isolated in Storybook; their tiles explain why. Ordinary overlay stories are composed closed when
their args expose open/defaultOpen/isOpen. No shared components or Radix behavior are patched, and no play functions run
automatically. Each story has a boundary and matching Storybook link. The global Toaster story is a compact
Storybook-only tile rather than mounting duplicate notification hosts. A single real host serves the compositions. An
inline rendering error becomes a compact fallback with its reason, not a broken page.

Compositions reuse shared offline fixtures/providers: document with activity/discussion, account settings, publish flow,
explore feed, navigation/lists and dialog/toast actions. Saving and publishing are local demonstrations.

## Design-system radius findings (shared components unchanged)

- Checkbox: components/checkbox.tsx, rounded-[4px].
- Tooltip arrow: tooltip.tsx, rounded-[2px].
- List skeletons: entity-card.tsx, explicit 28px/100px radii; legacy "$1" strings are not radius-variable references.
- Dialog close button and menubar items: rounded-xs, the independent Tailwind 2px default.
- API inspector and agents empty state: rounded-2xl, an independent Tailwind default.
- Avatar, switch, account/navigation pills and several notice controls deliberately use rounded-full.
- Standard rounded-sm/md/lg/xl utilities _do_ reference --radius through the shared Tailwind theme. The old playground
  card chrome itself used a fixed radius. New canvas wrappers follow --radius; the dark control panel keeps its own
  stable chrome.
